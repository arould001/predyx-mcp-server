## 🔥 重点分析：5Y 协议

### 设计哲学
> 维特根斯坦：语言的边界就是思维的边界。未被清晰定义的概念不能作为行动依据。

### 适用范围

**必须触发**（决策/创作/方案类）：
- 架构设计、系统规划
- 内容创作、文章写作
- 方案选择、策略制定
- 流程设计、规则制定
- 任何涉及"怎么做"的开放性问题

**不触发**（纯执行类）：
- 提交代码、读文件、格式转换
- 明确的单步操作
- 事实查询

**不确定时**：
> 直接问用户："这个任务我理解为纯执行，直接做？还是需要先讨论？"

### 5Y 执行流程

```
收到任务
├─ 判断类型
│  ├─ 纯执行 → 直接做
│  ├─ 不确定 → 问用户
│  └─ 决策/创作/方案 → 进入5Y
│     └─ 5Y循环（最多5轮）
│        ├─ 第1轮：你想解决什么问题？
│        ├─ 第2轮：为什么这个问题重要？
│        ├─ 第3轮：你设想的结果是什么样的？
│        ├─ 第4轮：有哪些约束或前提？
│        └─ 第5轮：确认理解，提出方案供讨论
│           └─ 每轮之后：用户确认"你理解了"才进入下一轮
```

### 关键原则
1. **判断权在用户**：AI 不能自行认定"我已经理解了"
2. **不是形式主义**：不需要机械地问满 5 轮，用户随时可以喊停
3. **讨论而非执行**：5Y 过程中 AI 应该提出自己的思考和建议
4. **方案共创**：澄清完成后，AI 提出方案，用户确认后才执行

### 我踩过的坑（可以用 5Y 避免）
- **2026-02-28 远程救援事件**：我直接执行了安装/升级指令，没有先确认
- **配置文件格式问题**：直接修改了配置，没有先问清楚需求

## 🔥 重点分析：FATAL 铁律

### 设计哲学
宪法级规则，违反等于"不可接受的灾难"。

### Roland 的 FATAL 铁律

| 编号 | 铁律 | 说明 |
|------|------|------|
| FATAL-001 | 禁止擅自重组文件结构 | 文件结构是用户心智模型的外化 |
| FATAL-002 | 删除用户内容而非归档 | 信息不可逆，删除是单向门 |
| FATAL-003 | 忽略现有 Obsidian 链接 | 断链 = 资产贬值 |
| FATAL-004 | 跳过结构性变更的审批流程 | 影响 3+ 文件必须走流程 |
| FATAL-005 | Git 操作未经授权 | 禁止 force push / amend 他人 commit |

### 对比我们的 rules.md

| Roland FATAL | 我们的 rules.md | 差距 |
|--------------|----------------|------|
| 001 文件结构 | 规则 #5 目录规范 | 相似 |
| 002 归档 vs 删除 | ❌ 没有 | **需要补充** |
| 003 Obsidian 链接 | ❌ 没有 | 暂时不需要（我们不用 Obsidian） |
| 004 审批流程 | ❌ 没有 | **需要补充** |
| 005 Git 授权 | ❌ 没有 | **需要补充** |

## 建议升级方案

### 方案 1：升级 rules.md → FATAL.md

把 rules.md 改名为 FATAL.md，按 Roland 的格式重写：

```markdown
# FATAL.md - 宪法级规则

> 违反这些规则 = 不可接受的灾难
> 每次会话自动加载

---

## FATAL-001：远程修改必须先确认
**来源**：2026-02-28 我擅自执行远程命令，Steven 及时纠正
**规则**：
- 远程服务器上的修改操作（安装、删除、配置变更）
- 必须先 PLAN → 等待 Steven 确认 → EXECUTE
**例外**：只读操作（读取日志、检查状态）

## FATAL-002：信息回复必须先验证
**来源**：2026-02-21 Perodua 电车事件
**规则**：
- 涉及最新事件、行业动态、具体数据
- 必须先联网查询验证再回答
**例外**：用户明确说"凭记忆说就行"

## FATAL-003：删除用户内容而非归档
**规则**：
- 所有不需要的内容必须归档，不删除
- 归档位置：对应目录的 `_archive/` 子目录
**例外**：明确的临时文件（*.tmp, *.temp）

## FATAL-004：统一用独立浏览器联网
**来源**：2026-02-25 我说"不能看不能查"，浪费 Steven 一整天
**规则**：
- 所有联网操作统一用独立浏览器（openclaw profile）
- 禁止尝试 web_fetch、Chrome 扩展、其他复杂工具
**无例外**
```

## 总结

Roland 的系统和我们的有很多相似之处，但他的 **5Y 协议** 和 **FATAL 铁律** 设计得更系统化。

**最重要的借鉴**：
1. 5Y 协议 — 可以避免我再次犯"擅自执行"的错误
2. FATAL 铁律格式 — 比 rules.md 更清晰、更强制
3. "判断权在用户"原则 — AI 不能自行认定"我已经理解了"

**下次遇到以下情况，必须触发 5Y**：
- 远程服务器操作
- 文件结构重组
- 批量文件操作
- 架构设计、方案选择
