## 一、六层架构视角

### 核心洞察

> 只强化其中一层，系统就会失衡

```

│                 Claude Code 六层架构          │

│  └─ Memory                                  │

│  ├─ Hooks                                   │
│  ├─ 权限                                    │
```

## 二、Token 成本真相

### 真实的上下文成本构成

```
200K 总上下文
├── 固定开销 (~15-20K)
│   ├── 系统指令: ~2K
│   ├── 所有启用的 Skill 描述符: ~1-5K
│   ├── MCP Server 工具定义: ~10-20K  ← 最大隐形杀手
│   └── LSP 状态: ~2-5K
│
├── 半固定 (~5-10K)
│   ├── CLAUDE.md: ~2-5K
│   └── Memory: ~1-2K
│
└── 动态可用 (~160-180K)
    ├── 对话历史
    ├── 文件内容
    └── 工具调用结果
```

### 关键洞察

> 一个典型 MCP Server（如 GitHub）包含 20-30 个工具定义，每个约 200 tokens，合计 **4,000-6,000 tokens**。接 5 个 Server，光这部分固定开销就到了 **25,000 tokens（12.5%）**。

**建议**:
- 只连接真正需要的 MCP Server
- 低频 MCP 考虑手动调用
- 定期用 `/context` 检查占用

## 三、Tool Output 噪声问题

### 问题

```
# Claude 看到的原始输出
running 262 tests
test auth::test_login ... ok
test auth::test_logout ... ok
...
（几千行）

# 这几千行挤掉的是：
- 对话历史
- 文件内容
- 你真正需要的信息
```

### 解决方案 1: 手动截断

```bash
# 所有长输出命令都加 | head -30
cargo test 2>&1 | head -30
git log --oneline | head -30
find . -name "*.rs" | head -30
```

### 解决方案 2: RTK（推荐）

> **RTK = Rust Token Killer**  
> 开源项目：https://github.com/rtk-ai/rtk

```
# Claude 看到的原始输出
running 262 tests
test auth::test_login ... ok
...（几千行）

# 走 RTK 之后
✓ cargo test: 262 passed (1 suite, 0.08s)
```

**核心价值**: Claude 只需要知道「过了还是挂了，挂在哪里」，其他都是噪声。

## 四、Compact Instructions

### 问题

默认压缩算法会丢掉：
- 早期的 Tool Output
- 早期加载的文件内容
- **架构决策和约束理由**（最致命）

### 解决方案

在 CLAUDE.md 中写明压缩时必须保留什么：

```markdown
## Compact Instructions

When compressing, preserve in priority order:
1. Architecture decisions (NEVER summarize)
2. Modified files and their key changes
3. Current verification status (pass/fail)
4. Open TODOs and rollback notes
5. Tool outputs (can delete, keep pass/fail only)
```

## 五、HANDOFF.md（会话连续性）

### 问题

长会话压缩后，下一个 Claude 实例不知道之前做了什么

### 解决方案

在开新会话前，让 Claude 写一份 HANDOFF.md：

```markdown
# HANDOFF.md - 当前任务交接

## 进展
- ✅ 已完成：用户认证 API
- 🔄 进行中：权限管理
- ❌ 阻塞：数据库迁移脚本

## 尝试过的方案
1. ✅ JWT 认证（已验证可行）
2. ❌ Session 认证（性能不达标）
3. 🔄 RBAC 权限（正在调试）

## 踩过的坑
- 密码必须用 bcrypt（不是 SHA256）
- Token 过期时间 7 天（不是 24 小时）
- Redis 缓存 key 必须加前缀

## 下一步
1. 完成权限管理 API
2. 添加单元测试
3. 更新 API 文档
```

**用法**:
1. 让 Claude 写 HANDOFF.md
2. 快速扫一眼，有缺漏直接补
3. 开新会话，把路径发给新 Claude

## 七、Skills 三种类型

### 类型 1: 检查清单型（质量门禁）

发布前跑一遍，确保不漏项：

```yaml
---
name: release-check
description: Use before cutting a release to verify build, version, and smoke test.
---

## Pre-flight (All must pass)
- [ ] `cargo build --release` passes
- [ ] `cargo clippy -- -D warnings` clean
- [ ] Version bumped in Cargo.toml
- [ ] CHANGELOG updated
- [ ] `kaku doctor` passes on clean env

## Output
Pass / Fail per item. Any Fail must be fixed before release.
```

### 类型 2: 工作流型（标准化操作）

配置迁移高风险，显式调用 + 内置回滚：

```yaml
---
name: config-migration
description: Migrate config schema. Run only when explicitly requested.
disable-model-invocation: true
---

## Steps
1. Backup: `cp ~/.config/kaku/config.toml ~/.config/kaku/config.toml.bak`
2. Dry run: `kaku config migrate --dry-run`
3. Apply: remove `--dry-run` after confirming output
4. Verify: `kaku doctor` all pass

## Rollback
`cp ~/.config/kaku/config.toml.bak ~/.config/kaku/config.toml`
```

### 类型 3: 领域专家型（封装决策框架）

运行时问题时让 Claude 按固定路径收集证据：

```yaml
---
name: runtime-diagnosis
description: Use when kaku crashes, hangs, or behaves unexpectedly at runtime.
---

## Evidence Collection
1. Run `kaku doctor` and capture full output
2. Last 50 lines of `~/.local/share/kaku/logs/`
3. Plugin state: `kaku --list-plugins`

## Decision Matrix
| Symptom | First Check |
|---|---|
| Crash on startup | doctor output → Lua syntax error |
| Rendering glitch | GPU backend / terminal capability |
| Config not applied | Config path + schema version |

## Output Format
Root cause / Blast radius / Fix steps / Verification command
```

## 八、disable-auto-invoke 策略

### 核心洞察

> 每个启用的 Skill，描述符常驻上下文，每个 Skill 都在偷你的上下文空间

### 使用策略

| 频率 | 策略 | 说明 |
|------|------|------|
| 高频（>1 次/会话） | 保持 auto-invoke | 优化描述符 |
| 低频（<1 次/会话） | disable-auto-invoke | 手动触发，描述符完全脱离上下文 |
| 极低频（<1 次/月） | 移除 Skill | 改为 AGENTS.md 中的文档 |

### 描述符优化

```yaml
# 低效（~45 tokens）
description: |
  This skill helps you review code changes in Rust projects. 
  It checks for common issues like unsafe code, error handling...
  Use this when you want to ensure code quality before merging.

# 高效（~9 tokens）
description: Use for PR reviews with focus on correctness.
```

## 九、内部工具演进

### AskUserQuestion 的三次迭代

| 版本 | 设计 | 问题 |
|------|------|------|
| V1 | 给 Bash 加 question 参数 | Claude 忽略参数，继续跑 |
| V2 | 约定 markdown 格式 | 没有 enforce，Claude 经常忘 |
| V3 | 独立 AskUserQuestion 工具 | **最稳定**，显式调用即暂停 |

### 设计原则

> 既然要 Claude 停下来问，就直接给它一个专门的工具。加 flag 或约定格式，它一顺手就略过去了。

### Todo 工具的教训

> 早期用 TodoWrite + 每 5 轮提醒，模型变强后反而成了限制。
> 
> 教训：当初加的限制，模型变强后可能变成枷锁。定期检查限制是否还成立。

### 搜索工具的演进

```
V1: RAG 向量数据库
    - 需要索引
    - 不同环境脆弱
    - Claude 不喜欢用
    
V2: Grep 工具
    - Claude 自己搜索
    - 更好用
    
发现: Claude 读 Skill → Skill 引用其他文件 → 模型递归读取
      → "渐进式披露" 模式
```

## 十、Hooks 输出截断

### 问题

Hook 输出也会污染上下文：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "pattern": "*.rs",
        "hooks": [
          {
            "type": "command",
            "command": "cargo check 2>&1",  // ❌ 可能几千行
            "statusMessage": "Running cargo check..."
          }
        ]
      }
    ]
  }
}
```

### 解决方案

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "pattern": "*.rs",
        "hooks": [
          {
            "type": "command",
            "command": "cargo check 2>&1 | head -30",  // ✅ 只留前 30 行
            "statusMessage": "Running cargo check..."
          }
        ]
      }
    ]
  }
}
```

**收益**: 100 次编辑，每次省 30-60 秒，累积省 1-2 小时

## 十一、Verifier 层级

### 三层验证体系

```
第 1 层: 命令级
├─ 退出码
├─ lint
├─ typecheck
└─ unit test

第 2 层: 集成级
├─ 集成测试
├─ 截图对比
├─ contract test
└─ smoke test

第 3 层: 生产级
├─ 生产日志验证
├─ 监控指标
└─ 人工审查清单
```

### 核心原则

> 假如一个任务你都说不清楚「Claude 怎么才算做对了」，那它大概率也不适合直接丢给 Claude 自动完成。

## 十二、高频命令工程意义

### 上下文管理

```bash
/context   # 查看 token 占用结构，排查 MCP 和文件读取占比
/clear     # 清空会话，同一问题被纠偏两次以上就重来
/compact   # 压缩但保留重点，配合 Compact Instructions
/memory    # 确认哪些 CLAUDE.md 真的被加载了
```

### 能力治理

```bash
/mcp         # 管理 MCP 连接，检查 token 成本，断开闲置 server
/hooks       # 管理 hooks，控制平面入口
/permissions # 查看或更新权限白名单
/sandbox     # 配置沙箱隔离，高自动化场景必备
/model       # 切换模型：Opus/Sonnet/Haiku
```

### 会话连续性

```bash
claude --continue            # 恢复当前目录最近会话
claude --resume              # 打开选择器恢复历史会话
claude --continue --fork     # 从已有会话分叉，同一起点不同方案
claude --worktree            # 创建隔离 git worktree
claude -p "prompt"           # 非交互模式，接入 CI
claude -p --output-format json  # 结构化输出
```

### 不常见但好用

| 命令 | 用途 |
|------|------|
| `/simplify` | 对刚改的代码做三维检查，直接修问题 |
| `/rewind` | 回到某个 checkpoint 重新来，不是"撤销" |
| `/btw` | 快速问侧问题，不打断主任务 |
| `/insight` | 让 Claude 分析会话，提炼值得沉淀的内容 |
| 双击 ESC | 回到上一条输入重新编辑 |

## 十三、高质量 CLAUDE.md 模板

```markdown
# Project Contract

## Build And Test
- Install: `pnpm install`
- Dev: `pnpm dev`
- Test: `pnpm test`
- Typecheck: `pnpm typecheck`
- Lint: `pnpm lint`

## Architecture Boundaries
- HTTP handlers live in `src/http/handlers/`
- Domain logic lives in `src/domain/`
- Do not put persistence logic in handlers
- Shared types live in `src/contracts/`

## Coding Conventions
- Prefer pure functions in domain layer
- Do not introduce new global state without explicit justification
- Reuse existing error types from `src/errors/`

## Safety Rails
### NEVER
- Modify `.env`, lockfiles, or CI secrets without explicit approval
- Remove feature flags without searching all call sites
- Commit without running tests

### ALWAYS
- Show diff before committing
- Update CHANGELOG for user-facing changes

## Verification
- Backend changes: `make test` + `make lint`
- API changes: update contract tests under `tests/contracts/`
- UI changes: capture before/after screenshots

## Compact Instructions
Preserve:
1. Architecture decisions (NEVER summarize)
2. Modified files and key changes
3. Current verification status (pass/fail commands)
4. Open risks, TODOs, rollback notes
```

## 十五、常见反模式汇总

| 反模式 | 问题 | 解决 |
|--------|------|------|
| CLAUDE.md 写太长 | 先污染自己上下文 | 保持短、硬、可执行 |
| 工具堆太多 | 选择混乱 | 按需加载，低频移除 |
| Subagents 到处开 | 状态漂移 | 显式约束权限和输出格式 |
| 跳过验证 | 出问题不知道哪里挂 | 必须有 Verifier |
| 长会话不清理 | 有效信息被淹没 | 任务切换用 /clear |
| 手动加时间戳 | 破坏 Prompt 缓存 | 放到消息里，不动 System Prompt |
| 会话中途切模型 | 重建缓存更贵 | 用 Subagent 交接 |
| Hook 输出不截断 | 反而污染上下文 | 所有命令加 \| head -30 |
