## 🔍 cmux 研究（18:17-19:17）

### 背景
Steven 要求研究 "Cmux" 项目，看它怎么用、有什么牛逼的地方。

### 发现：三个 Cmux 项目

1. **manaflow-ai/cmux** (7,375 ⭐) - **Steven 感兴趣的**
   - Ghostty-based macOS terminal
   - 专为 AI coding agents 设计
   - 垂直标签页 + 通知系统

2. **craigsc/cmux** (~96-347 ⭐)
   - "tmux for Claude Code"
   - Git worktrees 管理多 agents
   - 解决并行工作冲突

3. **soheilhy/cmux** (Go 网络库)
   - Connection multiplexer for GoLang

### manaflow-ai/cmux 核心价值

**痛点**：
- 同时跑多个 Claude Code / Codex sessions
- macOS 通知没有上下文
- Tab 开多了看不全

**解决方案**：
- **通知系统**：Blue ring + Tab 发光 + 通知面板
- **垂直标签页**：侧边栏显示 git branch、PR status、working directory、listening ports
- **内置浏览器**：Agents 可直接操作 dev server
- **原生性能**：Swift + AppKit，不是 Electron

### API 使用（主窗口派任务 + 信息交互）

**核心机制**：
- CLI + Socket API
- 主窗口 → `cmux send-surface` 派任务
- 子窗口 → `cmux set-status` / `log` / `notify` 汇报进度

**工作流**：
```
主窗口（Orchestrator）
  ├─ cmux new-workspace (创建子窗口)
  ├─ cmux send-surface (派任务)
  └─ cmux sidebar-state (收集状态)

子窗口（Agents）
  ├─ cmux set-status (状态 pill)
  ├─ cmux set-progress (进度条)
  ├─ cmux log (日志)
  └─ cmux notify (通知主窗口)
```

**Python Orchestrator 示例**：
- 通过 Socket API 创建 workspaces
- 派任务给各个 agents
- 监控进度（轮询 sidebar-state）

### 设计哲学（很赞）

> **"cmux is a primitive, not a solution."**
> 
> 不强迫工作流，给 primitives 让用户自己组合。

与 OpenClaw 理念一致 ✅
