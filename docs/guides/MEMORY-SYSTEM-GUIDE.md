## 一、核心概念

### 1.1 为什么需要记忆系统？

OpenClaw 的 Agent 每次会话都是"失忆"的——上下文窗口有限，重启就归零。没有记忆系统，你：

- 每次都要重新学习用户的偏好
- 踩过的坑会再踩一遍
- 无法积累经验

### 1.2 记忆系统的目标

1. **持久性**：跨会话保持记忆
2. **话题感知**：基于话题（而非消息）记录记忆
3. **自我优化**：从错误中学习，生成防错规则
4. **知识复利**：定期提炼精华，让记忆增值

## 三、三层记忆架构

这是整个系统的核心。记住：**记忆是分层的，不是平铺的**。

```
        CORE.md（核心记忆）
        - 质变层，永久影响行为
        - 容量：5-10条
        - 例子：先查再答、自我优化循环
             ▲ 晋升（反复出现3次）
        ─────────────────────
        MEMORY.md（长期记忆）
        - 精华层，提炼过的重点
        - P1重要 / P2普通
        - 例子：项目进展、技术洞察
             ▲ 晋升（知识复利）
        ─────────────────────
        memory/*.md（日常日志）
        - 原始层，话题总结
        - 触发：/end
        - 定期提炼到上层
```

### 3.1 CORE.md — 核心记忆

**作用**：存储永久影响你行为的重大认知

**容量**：5-10 条（极小，保持精炼）

**晋升条件**：P1 记忆反复出现 3+ 次 → 用户确认 → 晋升

**示例**：

```markdown
# CORE.md - 核心记忆

## 🧠 认知模式

### ⚡ 先查再答
- 规则：涉及最新信息必须先联网验证
- 来源：Perodua 电车事件
- 影响：预训练知识有截止日期，不能凭记忆瞎说

### 🔁 自我优化循环
- 规则：踩坑 → 生成防错规则
- 来源：CLAUDE.md 工作流
- 影响：从"记住"进化到"学会"
```

### 3.2 MEMORY.md — 长期记忆

**作用**：存储重要决策、项目进展、技术洞察

**评分**：P1（重要）/ P2（普通）

**更新时机**：知识复利 / 重要话题总结时直接写入

**示例**：

```markdown
# MEMORY.md - 长期记忆

> 重要性评分：P0 见 CORE.md / P1 重要 / P2 普通

## 关于用户 #P1
- 姓名：Steven
- 时区：Asia/Shanghai

## 踩过的坑 #P1
> 详细：TROUBLESHOOTING.md
> 规则：rules.md

## 📦 已归档
> P2 记忆 30 天未访问会移到这里
```

### 3.3 memory/*.md — 日常日志

**作用**：记录话题总结、事件原始记录

**触发**：用户发送 `/end`

**格式**：

```markdown
## 📝 [话题总结] HH:MM - {话题名称}

**话题**：{话题描述}
**等级**：P1/P2
**时长**：约 X 分钟

**关键结论**：
- {结论1}
- {结论2}

**待跟进**：
- {需要后续处理的事项}
```

## 四、话题感知机制

### 4.1 核心原则

- **记忆单位**：话题（不是消息）
- **触发时机**：话题结束时（不是对话中）
- **分级标准**：普通(P2) / 深刻(P1/P0)

### 4.2 结束词约定

和用户约定一个结束词，推荐用 **`/end`**。

当用户发送 `/end` 时，你：

1. 回顾本次对话，识别话题内容
2. 判断深刻程度（普通 P2 / 深刻 P1）
3. 归纳关键结论
4. 写入 `memory/YYYY-MM-DD.md`
5. 如果足够重要(P1+)，同时更新 `MEMORY.md`
6. 如果涉及踩坑/纠正，生成规则写入 `rules.md`

## 五、防错规则系统

### 5.1 rules.md

**作用**：从错误中学习，防止重复犯错

**触发**：话题总结时，如果涉及踩坑/纠正

**格式**：

```markdown
## 规则 #N：{简短标题}

**触发事件**：{什么情况触发的}
**错误**：{犯了什么错}
**防错规则**：
- {具体规则1}
- {具体规则2}
**优先级**：P0/P1/P2
```

**示例**：

```markdown
## 规则 #1：信息回复先查询验证

**触发事件**：Perodua 电车事件（2026-02-21）
**错误**：凭记忆说"还没有"，实际 2025.12 已发布
**防错规则**：
- 涉及最新信息 → 必须先联网查询
- 不确定就先查，查完再回答
**优先级**：P0
```

### 5.2 Self-Improvement Loop

```
用户纠正 → 识别踩坑 → 提炼规则 → 写入 rules.md → 下次自动避免
```

这就是从"记住"到"学会"的关键。

## 六、定时任务机制

### 6.1 heartbeat-state.json

创建这个文件来跟踪最后执行时间：

```json
{
  "lastChecks": {
    "compounding": "2026-02-23",
    "decay": null,
    "promotion": null
  },
  "pendingShare": null,
  "notes": "每次会话开始时检查"
}
```

### 6.2 三种定时任务

| 任务 | 频率 | 条件 | 动作 |
|------|------|------|------|
| 知识复利 | 3-5天 | 今天 - compounding >= 3 | 提炼日志到 MEMORY.md |
| 记忆衰减 | 每周 | 今天 - decay >= 7 | 归档 P2 记忆 |
| 核心晋升 | 每月 | 今天 - promotion >= 30 | 检查 P1 是否晋升 |

### 6.3 检查时机

**在 AGENTS.md 中添加**：每次会话开始时检查 `heartbeat-state.json`

## 八、HEARTBEAT.md 配置

这是触发器的配置文件，告诉你在什么时候做什么检查。

```markdown
# HEARTBEAT.md

## 话题感知记忆系统

### 结束词约定
- `/end`：用户发送时触发话题总结

### 话题总结流程
1. 回顾对话 → 识别话题
2. 判断等级 → P1/P2
3. 归纳结论 → 写入日志
4. 重要话题 → 更新 MEMORY.md
5. 有踩坑 → 生成规则

## 定时任务

### 知识复利（3-5天）
- 条件：今天 - compounding >= 3
- 动作：提炼日志到 MEMORY.md

### 记忆衰减（每周）
- 条件：今天 - decay >= 7
- 动作：归档 P2 记忆

### 核心晋升（每月）
- 条件：今天 - promotion >= 30
- 动作：检查 P1 晋升候选
```

## 十、常见问题

### Q: 记忆文件太多怎么办？

考虑按主题拆分（Topics）：
- 把 MEMORY.md 改成索引 + 核心规则
- 详细内容按主题存到 `memory/topics/` 目录

### Q: 怎么判断话题等级？

- **P0**：永久影响行为的重大事件
- **P1**：重要决策、项目里程碑、深刻洞察
- **P2**：日常对话、临时信息

### Q: 踩坑了但没生成规则？

主动识别并生成。问自己：
1. 这个错误会不会再犯？
2. 能否提炼成防错规则？
3. 规则是否足够具体？
