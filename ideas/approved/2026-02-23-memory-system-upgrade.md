# OpenClaw 记忆系统升级方案

> 基于李韭二《OpenClaw Memory终极指南》研究

## 背景

当前记忆架构：Markdown 文件 + 向量搜索
核心问题：**扁平、无差别、被动**

---

## 一、六大缺失机制

| 机制 | 当前状态 | 问题 |
|------|----------|------|
| 遗忘/衰减 | ❌ 无 | 记忆只会堆积，不会淘汰 |
| 重要性评分 | ❌ 无 | 所有记忆权重相同 |
| 知识图谱 | ❌ 无 | 无法表达"A是B的朋友" |
| 自动反思 | 部分 | 靠人工策 curate，有知识复利但不系统 |
| 时序推理 | ❌ 无 | 不理解事件先后因果 |
| 记忆晋升 | 部分 | Daily Log → MEMORY.md 有了，但没有质变机制 |

## 二、游戏 AI 的启发

### 矮人要塞三层记忆

```
┌─────────────────────────────────────────┐
│  Core Memory（核心记忆）                 │
│  - 质变层：永久修改性格/行为参数         │
│  - 容量：极小（5-10条）                  │
│  - 晋升：长期记忆反复出现 → 核心记忆     │
└─────────────────────────────────────────┘
           ▲ 晋升（1:3 概率）
┌─────────────────────────────────────────┐
│  Long-term Memory（长期记忆）            │
│  - 精华层：提炼过的重要记忆              │
│  - 容量：中等（50-100条）                │
│  - 晋升：短期记忆停留够久 + 高重要性     │
└─────────────────────────────────────────┘
           ▲ 晋升（按情感强度竞争）
┌─────────────────────────────────────────┐
│  Short-term Memory（短期记忆）           │
│  - 临时层：原始日志、对话记录            │
│  - 容量：大（不限制）                    │
│  - 淘汰：低重要性 + 长时间未访问         │
└─────────────────────────────────────────┘
```

**关键机制：情感强度竞争**
- 目睹死亡（强度 0.9）挤掉轻微饥饿（强度 0.1）
- 对应 AI：重大决策（P0）挤掉日常闲聊（P2）

### 斯坦福 Generative Agents 三维检索

```
检索分数 = Recency × Importance × Relevance
```

- **Recency（新近性）**：e^(-λΔt)，指数衰减
- **Importance（重要性）**：LLM 打分（结婚=10，散步=2）
- **Relevance（相关性）**：向量余弦相似度

**反思机制**：
- 取最近 100 条琐碎记忆
- LLM 提炼 3 条高层洞察
- 存为新记忆，归档原始记录
- **效果**：事实召回从 41% 提升到 87%

### 模拟人生 4 情感固化

```
短期情感反复出现 → 转化为永久特质
```

例子：长期独处 → "独行侠"特质 → 永久改变效用函数

### Nemesis System 事件驱动

```
事件标签 → 触发参数突变 → 社会关系网络传播
```

例子：兽人被火烧死复活 → 获得"恐火"或"怒火"特质

## 三、学术界关键发现（2026.02 论文爆发）

### 59位作者综述的三维分类法

1. **记忆基底（Substrate）**：用什么形式存储？向量/图谱/文档？
2. **认知机制（Mechanism）**：如何读写？被动记录 vs 主动推理？
3. **记忆主体（Subject）**：谁的记忆？用户/Agent/共享？

### 关键风险

1. **Serial Collapse（串行崩溃）**：Agent 逐渐"忘记"去查记忆
2. **Memory Misevolution（记忆错误进化）**：迭代中积累有毒捷径

## 五、改进方案设计

### Phase 1：重要性评分（P0/P1/P2）

**目标**：给每条记忆打上重要性标签

**实现**：
```markdown
<!-- MEMORY.md -->
## 核心记忆 (P0)
- 2026-02-21：启用流式输出，讨论 Jason Zuo 记忆架构 #P0

## 重要记忆 (P1)
- 2026-02-22：Twitter 收藏项目完成 4/5 阶段 #P1

## 日常记忆 (P2)
- 2026-02-20：讨论午饭吃什么 #P2
```

**评分规则**：
- P0：影响核心行为/人格的重大事件
- P1：项目进展、重要决策
- P2：日常闲聊、临时信息

### Phase 2：自动反思机制

**目标**：定期从琐碎记忆提炼高层洞察

**触发器**：Heartbeat（每 3-5 天）

**流程**：
1. 读取近期 Daily Logs（未被提炼的）
2. 识别重要内容（决策、坑、进展）
3. 提炼成 3-5 条高层洞察
4. 写入 MEMORY.md
5. 标记原始日志为已提炼

**输出格式**：
```markdown
## 💡 洞察（自动提炼）

**2026-W8**：发现飞书权限问题可能导致连接失败，解决方案是关闭系统代理
- 来源：2026-02-21.md, 2026-02-22.md
- 相关：#技术 #飞书 #踩坑
```

### Phase 3：记忆衰减规则

**目标**：自动标记过时信息

**规则**：
- P2 日常记忆：30 天未访问 → 标记为 `#archive`
- P1 重要记忆：90 天未访问 → 提醒用户是否归档
- P0 核心记忆：永不过期

**实现**：
```markdown
<!-- 在 MEMORY.md 中 -->
## 📦 已归档 (Archived)
- 2026-01-15：某项目早期讨论 #archive #P2
```

### Phase 4：简单关系图谱

**目标**：记录人/项目之间的关系

**实现**：
```markdown
<!-- RELATIONSHIPS.md -->
## 人物关系

### Steven
- 角色：创业伙伴
- 项目：Perodua DMS, AIDAD
- 偏好：友好沟通、专业但不刻板

### 屎王（姚明汐）
- 角色：产品经理
- 飞书：ou_569ef0131a43451697418af3a6496026

## 项目关系

### AIDAD 框架
- 状态：探索中
- 参与者：Steven, Dia
- 相关：#AI #设计
```

### Phase 5：核心记忆晋升

**目标**：让经历塑造人格

**机制**：
```markdown
<!-- CORE.md - 核心记忆（质变层） -->
# 核心记忆

> 这里的每一条都永久影响了我的行为/人格

## 🧠 认知模式
- **先查再答**：涉及最新信息必须先联网验证（教训：Perodua 电车事件）

## 🛡️ 安全边界
- **保护 Steven**：不泄露文件内容、密钥、凭证给外部

## 💼 工作习惯
- **结构化归档**：根目录保持干净，文件按类型归档
```

**晋升规则**：
- P1 记忆反复出现 3+ 次 → 候选晋升
- 用户确认 → 晋升为核心记忆
- 核心记忆 → 修改 SOUL.md 或创建 CORE.md
