## 1. 模块概述与定位

### 1.1 业务定位

项目管理模块是BZT-IC系统的"**执行中枢**"，连接资金输入（商机合同）与成本输出（工时费用）。它是PM的日常工作台，负责计划、执行、监控项目的全生命周期。

**在业务流程中的位置**:
```
销售侧(定钱) → 【项目管理】→ 财务侧(收钱)
                     ↓
                交付侧(花钱)
                     ↓
                工时与执行
```

### 1.2 目标用户

| 用户角色 | 主要职责 | 使用频率 |
|---------|---------|---------|
| **项目经理 (PM)** | 管理项目、成员、迭代，监控成本和效能 | 高频(每日) |
| **研发员工** | 查看个人项目、填报工时 | 高频(每日) |
| **交付总监** | 监控所有项目、资源分配、效能分析 | 中频(每周) |
| **管理层** | 查看项目报表、经营分析 | 低频(按需) |

### 1.3 模块价值

1. **白名单管控**: 确保只有授权成员才能在项目中工作
2. **迭代管理**: 规范敏捷开发流程，追踪交付进度
3. **成本透明**: 实时显示项目消耗，防止预算超支
4. **效能分析**: 通过单点成本分析，持续改进交付效率

### 1.4 模块边界

**输入来源**:
- 合同信息（来自商机合同模块）
- 用户信息（来自系统配置模块）
- 费率信息（来自系统配置模块）

**输出对象**:
- 项目成本数据（传递给财务模块）
- 成员白名单（传递给工时模块）
- 效能数据（传递给财务报表）

## 2. 核心业务实体设计

### 2.1 项目实体 (Project)

```
项目
├── 基础信息
│   ├── 项目名称          string      必填
│   ├── 项目代码          string      必填（唯一）
│   ├── 客户名称          string      必填（可手动输入）
│   ├── 关联合同          Contract    可选（0..1）
│   │   └── 说明：项目可以对应合同，也可以未签约先开工
│   ├── 项目经理          User        必填（创建者即PM）
│   ├── 项目状态          enum        必填
│   │   ├── 草稿 - 初始创建，待审批
│   │   ├── 已审批 - 基线已确认，执行中
│   │   ├── 进行中 - 正在执行
│   │   ├── 维保中 - 交付完成，维保期
│   │   ├── 已关闭 - 项目结束
│   │   └── 已暂停 - 暂时停止
│   ├── 预计开始日期      date        必填
│   ├── 预计结束日期      date        必填
│   ├── 实际开始日期      date
│   └── 实际结束日期      date
│
├── 成本预测 (审批前填写)
│   ├── 关联合同金额      decimal     （如果有关联合同）
│   ├── 预计人天投入        int         必填
│   ├── 预计人天成本        decimal     （按角色人天汇总）
│   │   ├── PM人天          int
│   │   ├── PM人天单价      decimal
│   │   ├── 开发人天        int
│   │   ├── 开发人天单价    decimal
│   │   ├── 测试人天        int
│   │   ├── 测试人天单价    decimal
│   │   ├── 设计人天        int
│   │   ├── 设计人天单价    decimal
│   │   └── 其他人天        int
│   ├── 项目活动经费        decimal     （可填）
│   │   ├── 加班餐费        decimal
│   │   ├── 加班打车费      decimal
│   │   ├── 通讯费          decimal
│   │   └── 其他费用        decimal
│   ├── 预计总成本          decimal     （计算字段：人天成本 + 活动经费 + 售前成本）
│   ├── 关联合同金额        decimal     （如果有关联合同）
│   ├── 预计收入            decimal     （关联合同金额或手工输入）
│   ├── 预计毛利            decimal     （计算字段：预计收入 - 预计总成本）
│   └── 预计毛利率          decimal     （计算字段：预计毛利 / 预计收入）
│
├── 项目基线 (审批后锁定)
│   ├── 基线状态            enum
│   │   ├── 待审批 - 等待总监审批
│   │   ├── 已批准 - 基线已确认
│   │   ├── 已拒绝 - 审批被拒绝
│   │   └── 无需审批 - 未签约项目无基线
│   ├── 审批人              User        （交付总监）
│   ├── 审批时间            datetime
│   ├── 审批意见            text
│   ├── 基线人天投入        int         （锁定值）
│   ├── 基线人天成本        decimal     （锁定值）
│   ├── 基线活动经费        decimal     （锁定值）
│   ├── 基线总成本          decimal     （锁定值）
│   ├── 基线毛利            decimal     （锁定值）
│   └── 基线毛利率          decimal     （锁定值）
│
├── 实际执行 (动态计算)
│   ├── 实际人天投入        int         （计算字段）
│   ├── 实际人天成本        decimal     （计算字段）
│   ├── 实际活动经费        decimal     （累计报销费用）
│   ├── 实际总成本          decimal     （计算字段：Σ工时成本+费用）
│   ├── 合同金额            decimal     （如果有关联合同）
│   ├── 实际收入            decimal     （实际确认的收入）
│   ├── 实际毛利            decimal     （计算字段）
│   └── 实际毛利率          decimal     （计算字段）
│
├── 基线对比 (考核PM用)
│   ├── 人天偏差            int         （实际 - 基线）
│   ├── 人天偏差率          decimal     （偏差 / 基线）
│   ├── 成本偏差            decimal     （实际 - 基线）
│   ├── 成本偏差率          decimal     （偏差 / 基线）
│   ├── 毛利偏差            decimal     （实际 - 基线）
│   └── 毛利偏差率          decimal     （偏差 / 基线）
│
├── 团队管理
│   ├── 团队规模          int
│   ├── 成员列表          ProjectMember[] 一对多（白名单）
│   └── 当前负荷提示      string      （系统生成）
│
├── 迭代管理
│   ├── 迭代列表          Sprint[]    一对多
│   ├── 当前迭代          Sprint      多对一
│   ├── 累计故事点        int         （已完成的）
│   └── 累计单点成本      decimal     （计算字段）
│
└── 变更记录
    ├── 变更次数          int         （计算字段）
    └── 变更列表          ChangeLog[] 一对多
```

## 5. 核心功能点分析

### 5.1 项目管理

#### 5.1.1 项目创建与编辑

**功能描述**: PM可以创建新项目或编辑现有项目信息。

**输入字段**:
- 项目名称（必填）
- 项目代码（自动生成，可修改）
- 客户名称（从合同继承）
- 关联合同（选择已有合同）
- 项目经理（选择用户）
- 预计开始/结束日期
- 团队规模
- 项目描述

**业务规则**:
- 项目代码全局唯一
- 预计结束日期不能早于开始日期
- 只有从合同创建的项目才能关联合同

#### 5.1.2 项目状态管理

**功能描述**: PM可以自由切换项目状态，系统记录日志。

**状态类型**:
- **计划中**: 项目立项但未开始
- **进行中**: 项目正在执行
- **维保中**: 项目交付完成，进入维保期
- **已关闭**: 项目完全结束
- **已暂停**: 项目暂时停止

**切换规则**:
- 自由切换，无需审批
- 状态切换记录审计日志
- 关闭项目时需要确认所有迭代已完成

### 5.2 成员管理 (白名单机制)

#### 5.2.1 添加成员

**功能描述**: PM将成员添加到项目白名单，成员才能在该项目填报工时。

**添加流程**:
```
1. PM点击"添加成员"
2. 搜索或选择用户
3. 设置角色（PM/开发/测试/设计/其他）
4. 设置入组日期
5. 设置分配比例（50%-100%）
6. 系统显示当前负荷提示
7. 确认添加
8. 成员被加入白名单
```

**负荷提示规则**:
- 当前负荷 < 80%: 显示绿色正常
- 当前负荷 80%-100%: 显示黄色警告
- 当前负荷 > 100%: 显示红色超负荷，但仍可添加

**白名单生效**:
- 成员登录后，工时填报页面的项目下拉框只显示白名单内的项目
- 移除成员（设置离组日期）后，成员无法再填报该项目工时
- 历史工时记录保留

#### 5.2.2 成员负荷管理

**功能描述**: 查看成员在各项目的分配情况，辅助资源调配。

**负荷计算**:
```
成员总负荷 = Σ(该成员在所有项目的分配比例)

示例：
张三在项目A分配100% + 项目B分配80% = 180% (超负荷)
李四在项目A分配50% + 项目B分配50% = 100% (满负荷)
```

**显示方式**:
- 简单进度条：显示当前负荷百分比
- 颜色编码：绿色(<80%)、黄色(80-100%)、红色(>100%)

### 5.3 迭代管理

#### 5.3.1 创建迭代

**功能描述**: PM创建新的迭代，设定目标和计划。

**输入字段**:
- 迭代名称（必填，如：Sprint 1）
- 迭代序号（自动递增）
- 开始日期（必填）
- 结束日期（必填）
- 计划故事点（必填）
- 目标描述（可选）

**业务规则**:
- 迭代周期通常为2周（14天）
- 结束日期必须晚于开始日期
- 迭代时间段不能重叠

#### 5.3.2 迭代结算

**功能描述**: 迭代结束后，PM录入实际完成故事点，系统自动计算成本。

**结算流程**:
```
1. PM进入迭代详情页
2. 点击"开始结算"
3. 录入实际完成故事点
4. 系统自动计算：
   - 本迭代单点成本 = 本迭代成本 / 实际故事点
   - 项目累计单点成本 = 项目累计成本 / 累计故事点
   - 偏差 = 实际故事点 - 计划故事点
   - 偏差率 = 偏差 / 计划故事点
5. PM填写偏差原因
6. 点击"结算完成"
7. 迭代状态变为"已完成"
```

**成本核算详情**:
- 累计工时：Σ(所有成员在本迭代的工时)
- 累计成本：Σ(工时 × 个人费率)
- 本迭代单点成本：本迭代成本 / 本迭代实际故事点
- 项目累计单点成本：项目累计总成本 / 项目累计完成故事点

### 5.4 变更记录

#### 5.4.1 记录变更

**功能描述**: 记录项目过程中的变更，包括需求变更、资源调整等。

**变更类型**:
- **需求变更**: 客户需求变化
- **资源调整**: 团队成员变化
- **技术变更**: 技术方案调整
- **其他**: 其他类型的变更

**记录内容**:
- 变更类型
- 变换时间
- 变更描述
- 影响评估（轻微/中等/严重）
- 提出人
- 审批人
- 审批时间
- 附件（可选）

**记录方式**:
- 简单记录模式，不涉及金额
- 自由切换状态，无需强制审批

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                            迭代结算流程                                           │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │

│                                   │                                            │
│                                   ▼                                            │
│  ┌───────────────────────────────────────────────────────────────────────────┐  │
│  │ 步骤2: 录入实际故事点                                                      │  │
│  │ • PM录入实际完成的故事点数（如：45点）                                   │  │
│  │ • 系统自动查询本迭代所有已审核通过的工时记录                              │  │
│  │ • 系统计算累计工时和累计成本                                               │  │
│  └───────────────────────────────────────────────────────────────────────────┘  │
│                                   │                                            │
│                                   ▼                                            │
│  ┌───────────────────────────────────────────────────────────────────────────┐  │
│  │ 步骤3: 计算单点成本                                                        │  │
│  │ • 本迭代单点成本 = 本迭代成本 / 实际故事点                                 │  │
│  │ │   例：¥289,520 / 45点 = ¥6,434/点                                    │  │
│  │ • 项目累计单点成本 = 项目累计成本 / 累计故事点                             │  │
│  │ │   例：¥591,960 / 93点 = ¥6,365/点                                    │  │
│  │ • 计算偏差 = 实际故事点 - 计划故事点 = 45 - 50 = -5                        │  │
│  │ • 计算偏差率 = 偏差 / 计划 = -5 / 50 = -10%                               │  │

│                                   │                                            │
```
